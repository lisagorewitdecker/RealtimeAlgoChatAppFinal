# Debugging the Expo Go client

The development app uses Replit's managed `artifacts/chat-app: expo` workflow. To test React Native DevTools on a physical phone, open **Preview on your phone** in Replit, follow any Expo Go sign-in steps shown there, and scan its current QR code. In the running app, open the Expo developer menu and select **Open Debugger**. Check that the debugger shows live tools (for example, Console or Components), not just an opening screen. Keep the managed workflow running; do not start a second Metro server or replace its managed sign-in.

The workspace's Nix desktop libraries are declared in `.replit`. The managed Expo start command passes Replit's library search paths through `LD_LIBRARY_PATH` so the desktop DevTools shell can load GLib and its other native dependencies on a fresh start. If preparation fails, check the managed workflow log for a missing shared library. With an inspector target present in `/json/list`, opening its debugger should show a `React Native DevTools` desktop window; also confirm `/status` still returns `packager-status:running`. An empty `/json/list` means a device needs to reconnect before this launch check can be completed.

To catch missing desktop libraries without a phone, run `pnpm --filter @workspace/chat-app run check:debugger` in the Replit workspace. This uses the same library-path wrapper as the managed Expo start command and asks React Native to prepare the cached DevTools shell (or download it if not yet cached) and run its `--version` check. It fails with an explanation if the Replit library path is absent, the Expo command no longer uses the wrapper, or the shell cannot load. The first run may need to download the shell; later runs use the cache. This does not start Metro, change Expo Go sign-in, or prove that live tools connect to a phone.

If the phone shows `[runtime not ready]: Cannot find native module "ExpoAsset"` after a workflow restart, first force-close Expo Go and rescan the *current* Preview QR code. This resolved a stale phone session on 2026-09-25 without changing dependencies. If it persists, check that the installed Expo Go build supports the app's SDK and run the Expo dependency checks before changing the project.

The React Native DevTools shell process and a 1200 × 600 `React Native DevTools` window were visible on the workspace's graphical display, and `/status` still returned `packager-status:running`. This verifies the shell opens for the attached target; the live-tools interaction itself was user-reported. D-Bus/GSettings warnings appeared in the shell log but did not stop the window from opening.
